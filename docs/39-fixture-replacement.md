# 39 — Public fixture replacement (decision 2026-11-22)

- **Status:** Accepted
- **Date:** 2026-11-22
- **Resolves:** open action 1 of [v1 scope and provenance](14-v1-scope-provenance.md)
- **Related:** [Private test fixtures](38-private-fixtures.md), [Document schema](13-document-schema.md), [Testing](06-testing.md)

## Decision

Replace the example/template fixtures and the Visio-exported PNGs **instead of** seeking legal clearance for them.

The set that may be published is `fixtures/public/`: seven drawings generated by LayoutCraft's own engine from drawing operations in
`rust/layoutcraft-fixtures`. Nothing in it comes from Microsoft, a stencil vendor or a Visio render. Its provenance is recorded in
`fixtures/public/provenance.json` as `self-authored`, `cleared` and redistributable under MIT OR Apache-2.0.

The Visio-authored corpus and the Visio `Page.Export` PNGs are **not** part of any distributed set. They stay in the private
validation location described in [Private test fixtures](38-private-fixtures.md) and remain an optional, internal oracle only.

## Why this route

The open question was a distribution question: may the project publish files made by, or derived from, Microsoft and vendor
material? We cannot answer that without a lawyer, and we do not need to if the project distributes no such material. Generating the
public fixtures ourselves removes the third-party content from the thing we publish, rather than asking for permission to publish
it. The legal question does not arise for material the project wrote itself.

This record is an engineering decision, not a legal opinion. It states what the project does: the public repository and the public
fixture set contain only our own work.

## What is in the public set

| Fixture | Covers |
|---|---|
| `public-basic-shapes` | Rectangle, rounded rectangle, ellipse, diamond, triangle, line, text box; fills, strokes, labels, text formatting |
| `public-connectors` | Two glued right-angle connectors between three shapes |
| `public-freeform` | Spline, arc, open polyline and closed polygon |
| `public-picture` | A picture from a PNG the generator draws (our own pixels) |
| `public-pages` | Two pages with page names and page operations |
| `public-groups` | Three shapes grouped as one unit |
| `public-text-and-data` | Multi-line bold/italic/underlined text, a Shape Data row, alt text |

Each fixture has:

- a source package under `fixtures/public/sources/`, written by `layoutcraft-engine` (the same writer the desktop app and the web shell
  use);
- a canonical golden model under `fixtures/public/models/`, produced by our importer;
- manifest hashes: source SHA-256, canonical model SHA-256, model-file SHA-256, counts, and the SHA-256 of every decompressed ZIP
  entry after a no-op patch save;
- a provenance record with the origin and licence.

`fixtures/public/manifest.json` follows `schema/golden-manifest-v1.schema.json`; the schema now allows `kind: "self-authored"`.

## How it stays ours

- The generator is `rust/layoutcraft-fixtures`; it draws with the same engine operations as a user of the app (`new_blank`, `draw`,
  `draw_curve`, `draw_arc`, `draw_polyline`, `insert_picture`, `add_connector`, `page_op`, `group_op`, `edit`).
- The PNG in `public-picture` is a checkerboard the generator paints; no third-party image is copied.
- The model and manifest are derived only from those generated packages. Model files are written with sorted keys, so a
  workspace-wide build (which enables `serde_json/preserve_order` through `layoutcraft-mcp`) produces the same text as the
  standalone generator.
- The regenerated test (`rust/layoutcraft-fixtures/tests/public_fixtures.rs`) fails if a committed source, model or manifest hash
  differs from what the generator produces, so a hand-edited or foreign file cannot slip into the set unnoticed.
- No Visio-rendered PNG is shipped. Visual comparison against Visio stays a private maintainer check; the public set makes no visual
  claim.

## Regenerate and check

```sh
cd rust
cargo run -p layoutcraft-fixtures --bin make-public-fixtures          # write sources, models, manifest, provenance
cargo run -p layoutcraft-fixtures --bin make-public-fixtures -- --check
cargo run -p layoutcraft-conformance -- --root .. --manifest ../fixtures/public/manifest.json
cargo test -p layoutcraft-fixtures
```

The conformance runner reports 44/44 checks for the seven fixtures with no visual manifest.

## What stays private, and why

`test/golden` (the 20 Visio-authored/probe sources, their canonical models and the 37 Visio page PNGs) is not distributed. The
private set is still useful: it teaches import behaviour that our own fresh output cannot exercise, and the Visio PNGs are the visual
oracle. It is kept for the maintainers' validation runs and is never published, packaged or embedded in a build for the public.

The fixture tests that read the private corpus keep their `cfg(private_fixtures)` gate. Their coverage is unchanged; what changes is
that the public repository no longer needs a licence decision to ship its own fixture contract.

## Consequences

- A public clone and public CI can run a real golden-fixture contract without third-party material.
- The public set tests our own writer/importer round-trip and rendering inputs; it does not replace the private Visio corpus as a
  behavioural oracle. Those two roles are now explicit.
- Regenerating `fixtures/public` is deliberate: change the generator, run it, and commit the new sources, models, manifest and
  provenance together. The regenerated test is the guard.
- The private golden models are refreshed with `refresh-golden-models` as before; they are not the public contract.
