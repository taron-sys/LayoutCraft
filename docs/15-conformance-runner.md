# Native conformance runner

The first Rust port component is `rust/layoutcraft-conformance` — a browser-free
CLI that reads [`test/golden/manifest.json`](../test/golden/manifest.json) and
validates either the fixture set itself or a port's candidate outputs.

See [`rust/README.md`](../rust/README.md) for build instructions and the full
candidate layout.

## What it checks

Without candidate options:

- manifest and document schema versions;
- source byte counts and SHA-256;
- golden model file hashes and canonical model hashes;
- golden `schemaVersion` and page/shape/connector/media counts;
- every Visio page-PNG reference's bytes, SHA-256 and dimensions.

With `--candidate-models`, `--candidate-patches` and/or `--visuals`:

- candidate model JSON compared semantically to the golden model (object order
  irrelevant, numeric tolerance configurable);
- candidate schema version;
- every decompressed ZIP entry's SHA-256 and entry count for an untouched patch;
- optional candidate page PNGs, letterboxed to 640×480 and compared with the
  visual manifest's pixel-delta / mismatch / mean-error thresholds.

It does not load Visio, launch a browser, import VSDX, or render pages itself.
`layoutcraft-vsdx` produces candidate model files and `layoutcraft-render` produces
candidate page PNGs; this runner checks them. The current Rust renderer passes
37/37 visual pages through `--visuals` (188/188 visual checks).

## Commands

Linux/macOS:

```bash
cd LayoutCraft/rust
cargo build --release
./target/release/layoutcraft-conformance --root ..
```

Windows (MSVC linker is not installed here; MinGW is available):

```powershell
cd LayoutCraft\rust
cargo +stable-x86_64-pc-windows-gnu run --quiet -- --root ..
```

Candidate check against the JS generator's current model/patch outputs:

```powershell
cargo +stable-x86_64-pc-windows-gnu run --quiet -- --root .. `
  --candidate-models "..\test\golden\models" `
  --candidate-patches "..\..\visio-test-runs\golden\patches"
```

Optional visual comparison:

```powershell
cargo +stable-x86_64-pc-windows-gnu run --quiet -- --root .. `
  --visuals "..\..\visio-test-runs\golden\visual-candidate"
```

Expected candidates live at `<dir>/models/<id>.json` and
`<dir>/patches/<id>.<ext>`; the runner also accepts `<id>-<savedName>` and
`<savedName>`.

When the private corpus is linked into the working tree with directory junctions
(`docs/38-private-fixtures.md`), `canonicalize` resolves `test/` and `examples/`
outside `--root`. Add the two directories as allowed roots:

```powershell
cargo +stable-x86_64-pc-windows-gnu run --quiet -- --root .. `
  --allow-root ..\test --allow-root ..\examples
```

## Current result

- No-candidate fixture/reference verification: **273/273** checks
  (122 model/package + 151 visual-reference checks).
- With `--no-visuals` (visuals unavailable): **122/122** fixture checks and
  **202/202** with candidate models/patches.
- Candidate models + untouched patches + visual references: **353/353**.
- Optional candidate page PNGs add 37 comparisons (390 checks total); the
  current JS renderer is diagnostic and does not pass all pages, because page
  backgrounds and theme fidelity are known gaps. The references target the Rust
  renderer, not the JS baseline.
- Rust unit tests: **4/4** (JSON equality/tolerance and JS-compatible number
  formatting).

`serde_json` uses the `float_roundtrip` feature so canonical hashes match the
JS harness, and the runner implements ECMAScript fixed/exponent formatting for
`modelSha256`. The manifest also stores `modelFileSha256` for cheap,
browser-free file integrity.

## Public self-authored set

`fixtures/public/manifest.json` is the redistributable fixture contract,
generated by `layoutcraft-fixtures` from our own drawing operations
([Public fixture replacement](39-fixture-replacement.md)). It has no visual
manifest, so the runner skips visual references:

```bash
cargo run -p layoutcraft-conformance -- --root .. --manifest ../fixtures/public/manifest.json
```

Result: **44/44** checks for seven fixtures.

## Remaining limits

- The runner validates artifacts; it is not the VSDX importer or renderer.
- Visual comparison is a smoke check, not pixel parity; font/locale/theme
  tolerance is documented in `test/golden/visuals/README.md`.
- `--no-visuals` skips visual references entirely for a port that has not copied
  the validation-only PNGs.
- It does not enforce fixture provenance. The redistributable set's provenance
  is checked by `layoutcraft-fixtures`; see
  [Public fixture replacement](39-fixture-replacement.md).
- A deliberate model change must regenerate the manifest/models in the same
  change.
