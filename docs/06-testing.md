# 6. Testing

## What runs in a public clone
- `cargo test --workspace` (from `rust/`) runs every test that needs no private fixture: unit tests of all crates, the model and the editing logic on generated documents, the app's logic tests, and the self-authored public golden set. Set `LAYOUTCRAFT_PUBLIC_BUILD=1` to build exactly what this repository builds (no private theme data).
- The redistributable golden set is `fixtures/public/`, generated by `layoutcraft-fixtures` from our own drawing operations ([Public fixture replacement](39-fixture-replacement.md)). `cargo test -p layoutcraft-fixtures` and `layoutcraft-conformance --manifest ../fixtures/public/manifest.json` check it without any third-party file.
- Tests that read the private corpus (Visio-made drawings, golden models, oracle data) are compiled only when that corpus is present (`cfg(private_fixtures)`, set by the `build.rs` of the crate). Without it they do not exist, so the clone builds and passes. See [Private test fixtures](38-private-fixtures.md).

## What the maintainers run additionally
- With the private corpus linked in, `cargo test --workspace` runs everything (several hundred more tests).
- The conformance runner (`layoutcraft-conformance`, see [Native conformance runner](15-conformance-runner.md)) compares the core against recorded results of Microsoft Visio.
- Scripted checks of the browser shell and of both MCP servers, and comparisons against a licensed Visio installation on a maintainer's machine. They need the private repository and Visio, and are not part of the public build.

## Writing tests
- Prefer generated fixtures: build the document with the engine or the writer inside the test. A fixture committed to this repository must be our own work (see `AGENTS.md`).
- Assert relations ("inside", "wider than", "changed"), not exact values we merely chose.
- A bug fix adds a test that fails without it.
