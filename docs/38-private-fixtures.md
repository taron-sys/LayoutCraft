# 38 - Private test fixtures (decision 2026-11-21)

**Decision (user, 2026-11-21): test files do not belong in the public repository.** `/test/` and `/examples/` are in `.gitignore`.

## Why
- A `.vsdx` / `.vssx` is not only test data: it carries shape artwork. The `*-masters.vsdx` files of `test/corpus` are masters taken from Microsoft's built-in Visio stencils (48 files), `awsgen-*` / `azure*` come from AWS / Microsoft Azure (3 files). `examples/` (about 20 GB: AWS, Dell, Cisco-style rack stencils, BPMN, Microsoft sample drawings) is third-party material with its own terms. The Source is from: https://github.com/bhdicaire/visioStencils
- Publishing them under MIT OR Apache-2.0 would claim rights over material that is not ours. That's why they are not shipped with the public build. 

## What is in `test/`
- `test/corpus/` (127 files): 51 stencil-master drawings (above) and 76 probe drawings made with Visio over COM (bevel-*, fill-patterns, route-sweep-*, linejump-*, layers-guides, ...) plus their numeric dumps (`*.json`, `*.tsv`) and Visio screenshots (`*.png`).
- `test/golden/` (golden models + patches: numeric dumps of the corpus), `test/drawio/`, `test/excalidraw/` (small hand-made or tool-made samples), a few loose drawings (`from nothing.vsdx`, `Network Overview.vsdx`, `MS Example-edited.vsdx`).

## How the tests cope
- Each crate with fixture tests (`layoutcraft-vsdx`, `-render`, `-engine`, `-model`, `-mcp`) has a `build.rs` that sets `cfg(private_fixtures)` when `../../test/corpus` exists. Integration test files that read fixtures start with `#![cfg(private_fixtures)]`, embedded tests that read fixtures carry `#[cfg(private_fixtures)]`.
- A public clone has no `test/`: `cargo test --workspace` runs only the tests that need no fixture and is green. With the private corpus in place everything runs as before (the gate, conformance, the oracles).
- Run the public check with `test/` and `examples/` moved away.

## How to supply the private corpus
Keep `test/` and `examples/` in a PRIVATE place (a private repository cloned next to or into `LayoutCraft/`, or a private git submodule). The folder names must stay `LayoutCraft/test` and `LayoutCraft/examples`. Never add them to the public repository; never publish a build artefact that embeds them (`web/` and the wasm do not).

## Distribution
The fixture and Visio-PNG question is resolved by replacement, not by clearance: the set that may be published is
`fixtures/public/`, generated by LayoutCraft's own engine and marked self-authored/cleared ([doc 39](39-fixture-replacement.md)).
Everything in the private corpus is validation-only and is not published, packaged or embedded. It s solely used for testng and verification of the software's function. Open legal questions remain only for material that would actually be published: the style sheets in `style_data.rs` and how
the README names Visio / `.vsdx` (it uses them descriptively). Do not move private corpus material into a public file.

## Verified 2026-11-21
- `cargo test --workspace` with the private corpus present: 90 result lines, 619 tests passed, 0 failed.
- The same with `test/` and `examples/` moved away and `LAYOUTCRAFT_PUBLIC_BUILD=1` (what a public clone builds): 90 result lines, 246 tests passed, 0 failed. So about 373 tests need the private corpus and are skipped publicly; replacing them with synthetic fixtures would raise the public coverage.
- Two build scripts that already existed (`layoutcraft-vsdx/build.rs`: private themes; `layoutcraft-mcp/build.rs`: Windows resources) were overwritten by mistake while adding the fixture switch and were rebuilt from the earlier build output; the full gate has not been re-run since (rerun it before the next release).

## How the public and the private repository fit together (2026-11-21)
- The public repository contains only the product source. The private material lives in a second repository (`LayoutCraft-private`, cloned next to this one): the test corpus and golden models (`overlay/test`), the additional private theme data (`overlay/private`), the derived oracle data of the engine tests (`overlay/oracle-engine`), notes that describe measuring Visio or contain legal and release preparation (`overlay/docs`), and the Visio probe scripts and test runners (`visio-test-harness`).
- `setup-links.ps1` in the private repository joins both with directory junctions (no copies, no administrator rights), so the working tree looks like the one the project was developed in. `.gitignore` and `.git/info/exclude` keep the linked folders out of this repository.
- The Visio example drawings and stencils (about 20 GB, third party from https://github.com/bhdicaire/visioStencils) are in neither repository: they stay on disk and are passed to `setup-links.ps1` with `-ExamplesDir`.
- `web/layoutcraft.wasm` is not committed: build it with `tools/build-web-wasm.sh public`.
