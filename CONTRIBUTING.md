# Contributing

Thank you for helping. Please read `AGENTS.md` first: it holds the rules for code, tests and provenance, and applies to people as well as to coding agents.

## Provenance (the part that cannot be relaxed)

LayoutCraft is an independent implementation. It contains no Microsoft code, assets, stencils or fonts. A behaviour must be justified by
public file-format documentation, files the application generates or saves, ShapeSheet cells read through the published automation
interface, observable COM state, or rendered pages, and the evidence is recorded; see [`PROVENANCE.md`](PROVENANCE.md). The project does
not claim a separated-team process or that these are the only sources ever consulted.

- Do **not** submit code, stencil geometry, icons, themes, fonts or text copied or derived from Microsoft Visio or any other product, and do not use decompiled or extracted code of any kind.
- Do **not** read or copy the source of GPL, LGPL or AGPL projects to learn how something is done.
- Test files must be your own work (generated by this program or drawn by hand). Do not add documents or stencils made by other people or by Visio itself.
- Every new asset needs its origin and licence recorded in the same pull request. New dependencies must be compatible with MIT OR Apache-2.0 (`cargo deny check` in `rust/` must pass).
- Use "Visio" and ".vsdx" only to say which file format is supported; do not suggest any affiliation with Microsoft.

## Licence of contributions

The project is available under MIT OR Apache-2.0, at your option. By submitting a contribution you agree it is licensed the same way. Please add a `Signed-off-by:` line to each commit
(`git commit -s`), which states that you wrote it or have the right to submit it (Developer Certificate of Origin 1.1, https://developercertificate.org/).

## Before you open a pull request

Run the checks for the crates you changed (see `AGENTS.md`, section "Pull requests"), say in the pull request what ran and what did not, and do not report a check that did not run as passed. Run `npm run check:provenance` (or `node tools/check-provenance.mjs`) before opening a pull request: it rejects unverifiable provenance wording, private paths and third-party packages in the publishable tree.
Security problems go to the private channel in `SECURITY.md`, never into a public issue.
