# Native Rust workspace

The Rust workspace's main crates are:

- `layoutcraft-model` — typed portable document model (schema v1).
- `layoutcraft-vsdx` — safe VSDX OPC package reader and model importer.
- `layoutcraft-render` — headless scene, SVG and `resvg` PNG raster path.
- `layoutcraft-app` — native `eframe`/`egui` shell: open, render, pan/zoom,
  select pages/shapes, move/resize ungrouped shapes, undo/redo and save a
  patched copy.
- `layoutcraft-conformance` — browser-free golden-fixture checker.
- `layoutcraft-fixtures` — generates the self-authored, redistributable public
  golden set in `fixtures/public/` (`make-public-fixtures`; see
  [`../docs/39-fixture-replacement.md`](../docs/39-fixture-replacement.md)).

`layoutcraft-conformance` is a browser-free Rust CLI for the portable LayoutCraft
golden fixtures. It reads `test/golden/manifest.json`, verifies the manifest,
source files and golden canonical models, and can compare a port's candidate
models and untouched VSDX patch outputs against the same manifest. It never
launches Brave, Visio or any other UI.

## Build and run

On Linux/macOS:

```bash
cd LayoutCraft/rust
cargo build --release
./target/release/layoutcraft-conformance --root ../..
```

On this Windows machine the MSVC linker is not installed, so use the GNU
toolchain (MinGW is available):

```powershell
cd LayoutCraft\rust
cargo +stable-x86_64-pc-windows-gnu build --release
cargo +stable-x86_64-pc-windows-gnu run --release -- --root ..
```

No-candidate mode checks:

- `manifestVersion` / `documentSchemaVersion`;
- every source file's byte count and SHA-256;
- every golden model file's `modelFileSha256`;
- the canonical model hash (`modelSha256`), using the same sorted-key,
  ECMAScript-number formatting as the JS harness;
- golden `schemaVersion` and page/shape/connector/media counts;
- every Visio page-PNG reference's bytes, SHA-256 and dimensions when
  `test/golden/visual-manifest.json` exists.

Current result: **273/273 checks** (122 model/package checks + 151 visual
reference checks). With `--no-visuals` the portable subset is **122/122**.

## Public, redistributable fixture set

`fixtures/public/manifest.json` is the self-authored set generated by
`layoutcraft-fixtures` from our own drawing operations. It ships no
Visio-authored package and no Visio-rendered image, so it may be redistributed.

```bash
cargo run -p layoutcraft-fixtures --bin make-public-fixtures          # regenerate
cargo run -p layoutcraft-fixtures --bin make-public-fixtures -- --check
cargo run -p layoutcraft-conformance -- --root .. --manifest ../fixtures/public/manifest.json
```

The last command reports 44/44 checks. The private `test/golden` set remains an
optional validation oracle (`docs/38-private-fixtures.md`).

## Candidate mode

A port can provide a directory with the conventional layout:

```text
candidate/
  models/<id>.json
  patches/<id>.<source-extension>
  visuals/<id>-p<page>.png       # optional
```

or individual directories:

```bash
layoutcraft-conformance --root ../.. \
  --candidate-models candidate/models \
  --candidate-patches candidate/patches \
  --visuals candidate/visuals
```

Patch lookup also accepts `<id>-<savedName>` and `<savedName>` inside the patch
directory. Candidate models are compared semantically to the golden model,
independent of object key order, with a configurable numeric tolerance
(`--tolerance`, default `1e-9`). Candidate patches are compared by the SHA-256
of every decompressed ZIP entry.

Current verification using the JS generator's models and untouched patches:

```powershell
cargo +stable-x86_64-pc-windows-gnu run --release -- --root .. `
  --candidate-models "..\test\golden\models" `
  --candidate-patches "..\..\visio-test-runs\golden\patches"
```

Result: **353/353 checks** (models, patches and visual references), or
**202/202** with `--no-visuals`.

Optional visual comparison of candidate page renders:

```powershell
cargo +stable-x86_64-pc-windows-gnu run --release -- --root .. `
  --visuals "..\..\visio-test-runs\golden\visual-candidate"
```

The visual mode letterboxes both images onto a 640×480 white canvas, then
applies the manifest's pixel-delta / mismatch / mean-error thresholds. Font,
locale and theme differences are expected; this is a smoke check, not pixel
parity. The current JS renderer is diagnostic and intentionally not a v1 gate
(page backgrounds/theme fidelity are known gaps).

## Semantics and limits

- The conformance runner does not import shapes itself. `layoutcraft-vsdx`
  currently reads packages, relationships and page metadata; a future shape
  importer produces candidate model/patch files for this tool.
- It does not render pages and does not require Visio. Visual checks compare
  supplied PNGs only.
- It refuses manifest paths that escape the source root (no `..` traversal).
- ZIP entries are read in memory; it never extracts archives to the filesystem.
- `serde_json` is built with `float_roundtrip`; the canonical hash serializer
  reproduces ECMAScript's fixed/exponent number formatting so `modelSha256`
  can be verified exactly.
- A deliberate model change requires regenerating `test/golden/` and updating
  the manifest; never compare canonical models across schema versions.

## Workspace

- `Cargo.toml` — workspace.
- `layoutcraft-model/` — typed `Document`/`Page`/`Shape`/`Connector`/media/data
  graphic model; loads all 20 canonical golden models and matches their counts.
- `layoutcraft-vsdx/` — safe OPC ZIP/XML/relationship reader; `Package::pages()`
  resolves page names/parts; `page_shapes()` parses recursive shape trees;
  `MasterCatalog` + `resolve_page_shapes()` resolve `Master`/`MasterShape` and
  merge master/page sections; `geometry.rs` builds paths for lines, arcs,
  ellipses, NURBS and splines; `import_document()` builds the editable model with
  boxes, rotated-group flattening, connectors, labels, Shape Data, pictures/
  media, rich text (runs/paragraphs/fields/text boxes), theme/StyleSheet/
  quick-style resolution and LayoutCraft-authored data-graphic metadata;
  `vsdx-inspect` prints page/shape/master counts.
- `layoutcraft-render/` — scene construction from a `Document` page, deterministic
  SVG output, `resvg`/`tiny-skia` PNG rasterization, picture crop/filter support,
  rich text with font-backed word wrapping, connectors with glue/waypoints and
  auto-routing. `render-page` renders model JSON; the `render_vsdx` example
  renders a VSDX page with picture bytes attached.
- `layoutcraft-app/` — the native shell. Opens a VSDX/VSTX via command-line path,
  path field or drag-and-drop, renders the current page through the same
  SVG/`resvg` path, and provides page navigation, fit/actual-size, pan, zoom,
  shape hit-testing and an inspector summary. Dragging moves shapes, corner
  handles resize, `Ctrl+Z`/`Ctrl+Shift+Z` undo/redo, and `Save copy` writes a
  patched sibling file. Grouped shapes are read-only and rotated shapes are
  move-only in this slice.
- `layoutcraft-conformance/` — the CLI; unit tests cover JSON equality and
  JS-compatible number formatting.
- `Cargo.lock` — pinned dependency versions for the initial port.

Run all tests and the VSDX inspector:

```powershell
cargo +stable-x86_64-pc-windows-gnu test --workspace
cargo +stable-x86_64-pc-windows-gnu run -q -p layoutcraft-vsdx --bin vsdx-inspect -- ..\examples\MS Example.vsdx
cargo +stable-x86_64-pc-windows-gnu run -q -p layoutcraft-render --example render_vsdx -- ..\examples\MS Example.vsdx 0 ..\..\visio-test-runs\ms.png
```

Run the native shell (add a path to open a drawing immediately):

```powershell
cargo +stable-x86_64-pc-windows-gnu run -p layoutcraft-app -- "..\examples\MS Example.vsdx"
```

On Linux use plain `cargo`. The shell also accepts drag-and-drop and a path in
the toolbar.

Current workspace tests: **40/40**; model golden fixtures **20/20**; VSDX

nested/rotated groups, connectors, pictures, rich text, theme/quick-style paints,
